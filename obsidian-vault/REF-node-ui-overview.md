## 전체보기 모드 (확정, 2026-09-30 구현 → `REF-node-ui-render.md` "전체보기 모드")
Windows Alt+Tab / Android·iOS 앱 전환처럼 **실행 중인 프로세스를 한 번에 보는 모드**.

| 항목 | 규칙 |
|---|---|
| 배치 | **현재 배치 그대로** — 같은 `toGrids` 결과를 실제 px 크기로 그린 뒤 `transform: scale(s)`로 축소, 칸은 축소 크기만큼만 차지 |
| 나열 방향 (확정) | Grid 영역 가로·세로 비교 → **긴 축을 따라 Grid를 한 줄로**(Grid 안 타일은 두 줄 가능), **짧은 축은 가운데 정렬**. PC = 가로 한 줄 + 세로 가운데 / 폰 세로 = 세로 한 줄 + 가로 가운데. 가로 한 줄이면 휠도 가로로 |
| 스크롤 | 자유 스크롤, **칼럼 스냅 끔**(스냅 앵커를 안 그림) |
| 타일 | 편집 버튼 비활성, 이름·상태 라벨은 역배율(`scale(1/s)`, 폭 `calc(100% * s)`)로 읽을 수 있는 크기 유지. 출력은 축소 상태에서도 계속 갱신. 폴더 타일은 흐리게. Grid 하단 정보 줄은 숨김(높이 = 타일 영역만) |
| 나가기 | 타일 누름(Enter/Space 포함) = 닫고 그 타일의 Grid로 이동 / Esc·돌아가기 = 들어오기 전 스크롤 위치로 |
| 축소 비율 (⑫ 확정 2026-09-30) | **사용자 조절** — 기본 30%, 15~60%, 5% 단위. 헤더 `- n% +` |
| 거르기 (⑫ 확정 2026-09-30) | **안 거름** — 배치 그대로가 원칙(거르면 Grid 모양이 달라져 누른 타일 위치·돌아갈 Grid가 어긋남). 폴더는 흐리게만 |

- **영역 크기(`capacity` 판정용)는 스크롤 영역이 아니라 프레임 기준**으로 잰다 — 전체보기의 스크롤바가 판정을 바꾸면 "배치 그대로"가 깨진다.

## 전체보기 버튼 (위치는 사용자가 더 검토 중)
- 화면에 **고정**(스크롤해도 제자리). **Grid 하단 정보 줄(`Grid 1 · column · 4타일`, 20px) 높이에 맞춘 작은 강조색 버튼**(22px, 정보 줄 가운데)을 **그 줄 오른쪽 끝**에 둔다 → 타일을 가리지 않음.
- 아이콘 = 2×2 사각형. Grid 영역 가로 용량 2칸이면 **아이콘+글자**, 1칸이면 **아이콘만**(`capacity.x` 재사용, 기준치 하나 더 만들지 않음). 전체보기 중에는 어두운 색 `돌아가기`(되돌리기 아이콘).
- 기각: v3 큰 떠 있는 버튼(44px, 16px 띄움) — 오른쪽 아래 타일을 가림.

## 스크롤바와 고정 버튼 (재발 방지)
- 함정: 두께를 차지하는 스크롤바(Windows/Linux 약 15px)가 Grid 개수에 따라 생겼다 사라지면 정보 줄 높이가 흔들려 고정 버튼과 어긋난다.
- **확정 대응 = `overflow: auto`(필요할 때만 보임) + 버튼이 현재 스크롤바 두께를 따라감**: 렌더 후 `offsetHeight - clientHeight`(가로 바) / `offsetWidth - clientWidth`(세로 바)를 `--sb-h`/`--sb-w`로 두고 버튼 `bottom: 7px + --sb-h`, `right: 8px + --sb-w`.
- **`capacity` 판정 높이에서는 스크롤바를 빼지 않는다** — 빼면 스크롤바 등장 → 칸 수 변화 → Grid 수 변화 → 스크롤바 소멸의 진동 위험.
- 기각: 항상 표시(`scroll`, Grid 1개일 때도 빈 스크롤바 줄) / 숨김(사용자: "필요하면 보여야 한다").

## 헤더 내비게이션 — Grid 탭 · 칼럼 위치 · 칼럼 이동
- **Grid 탭 = Vuetify `VPagination`으로 구현**(4.1.2 소스 확인):
  - `total-visible` 생략 시 ResizeObserver로 자기 폭을 재서 버튼 수 자동, `…` 내장. `total-visible="5"`면 정확히 `처음 … c-1 c c+1 … 끝`(대신 그것도 안 들어가는 폭에선 잘림).
  - ~~표시 이름 `G1`은 `item` 슬롯~~ → 구현은 **숫자만**(2026-09-29, 기본 버튼 스타일 상속 유지 — `REF-node-ui-render.md`). 부모 폭 제한 필요(flex 자식이면 `min-width: 0`) — 없으면 내용 폭을 재서 안 줄어듦.
  - `v-model`(1부터) 양방향 되먹임 방지: 스크롤 → 현재 Grid → 모델 갱신 / 클릭 → 스크롤은 `@update:model-value`에서만.
  - 현재 = 화면에 가장 많이 보이는 Grid, **동점이면 뒤쪽**(스크롤 끝 = 마지막 Grid). 다중 강조(1/4 보이면 파랑)는 VPagination이 지원 안 함 → 버림.
  - **확정(2026-09-29, G(화살표 = 칼럼 이동))**: VPagination prev/next 화살표 슬롯을 칼럼 단위 이동 ‹ ›로 교체(헤더 폭 절약), Grid 단위 이동은 탭 클릭. 구현 → `REF-node-ui-render.md` "헤더 내비".
  - 시안 v8 버그(참고): 줄인 목록이 들어가는지 재확인하지 않아, 한 칸 빈틈 채우기로 목록이 전부가 되면 `overflow:hidden`에 끝 페이지가 잘렸음. 시안 v9는 후보를 넓은 것부터 그려 보고 들어가는 첫 후보를 씀.
- **칼럼 위치 표시**: 왼쪽 칼럼 번호만 쓰면 한 화면에 2칼럼이 보일 때 끝에서도 `6/7`로 끝남 → **보이는 범위 `칼럼 6-7/7`**. 헤더의 다른 글자를 먼저 갱신한 뒤 남은 폭에 탭을 맞춘다.

## 모바일 가상 키보드 (2026-09-29 검토, 미확정)
터미널 타일에 입력하려고 포커스하면 가상 키보드가 뜬다(약 화면 높이 36~50%). 대응 없으면 아래 문제가 생긴다.

| 문제 | 무슨 일이 생기나 | 대응 (제안) |
|---|---|---|
| ① 배치 재계산 | 폰 세로 Grid 영역 높이 약 770 - 키보드 약 300 → 560 미만 → 세로 1칸 → 0.5 타일이 1.0으로 재배치 → 입력 중 타일이 다른 Grid로 밀림 → 포커스 잃고 키보드 닫힘 → 다시 2칸(반복 가능) | **`capacity` 판정은 레이아웃 뷰포트로만**(키보드 무시). `<meta viewport>`에 `interactive-widget=resizes-visual` 명시해 Android도 iOS처럼 키보드가 화면 위에 겹치게 통일 |
| ② 입력 중 타일 가려짐 | 폰 타일(세로 0.5) 약 380px, 아래쪽 타일이면 키보드에 통째로 덮임 | 키보드 떠 있는 동안 **포커스된 터미널만 보이는 영역(visualViewport)에 꽉 채우는 입력 모드**. 배치는 그대로, 표시만 겹침 |
| ③ PTY resize 연쇄 | 보이는 영역에 xterm을 다시 맞추면 키보드 열고 닫을 때마다 resize REST → htop 등 전체 다시 그림 | 입력 모드 터미널 크기: **유지 + 스크롤** vs **맞춤(resize 전송)** 중 선택 (→ `REF-process-resize.md`) |
| ④ 특수키 없음 | 가상 키보드에 Ctrl·Esc·Tab·방향키 없음, xterm 모바일 한글 조합 입력 불안정 | Termux식 **키보드 위 보조 키 줄**(visualViewport 기준 위치). input 배선 미착수라 설계에 포함 |
| ⑤ iOS 문서 스크롤 | iOS는 포커스된 입력칸을 보이려고 문서 전체를 밀어 올림 → 헤더가 화면 밖 | 앱 셸 문서 스크롤 막기 + visualViewport `offsetTop`/`height`로 입력 모드 위치 |

- **현재 코드 확인(2026-09-29)**: `index.html` viewport 메타에 `interactive-widget` 없음. `feature/layout/store/appWindown.store.ts`는 `window` `resize`만 듣고 `size.inner` = visualViewport 크기 → **타일 `capacity` 판정을 `inner`에 연결하면 ①이 그대로 발생**, `outer`(레이아웃 뷰포트)에 연결할 것. 입력 모드·보조 키 줄은 visualViewport `resize`/`scroll` 이벤트를 별도로 들어야 함.
- 시안(구현 기준 v10)에 폰 "가상 키보드" 토글 + 판정 기준 / 입력 모드 / 터미널 크기 비교 스위치를 넣음. 헤드리스 확인: 레이아웃 뷰포트 판정이면 키보드 열 때 자리 바뀐 타일 0개, 보이는 영역 판정이면 폰 Grid 영역 세로 770 → 428로 줄어 **13타일 전부 재배치(Grid 7 → 13개)** — ①이 실제로 크다는 근거.
