## 목적
계정 폴더 타일·터미널 타일과 같은 급의 **세 번째 타일 종류**. worker의 실제 디렉토리를 계정 폴더 타일과 거의 같은 UI로 보여 준다.
**핵심 = 보고 있는 위치에 업로드.** (덤: 이미지·텍스트를 새 타일로 보기 = 다음 파트)

| 번호(이름) | 사용자 설명 | 해석·영향 |
|---|---|---|
| 장비-1(루트 장비 타일) | 보드의 루트 타일이 될 수 있고, 루트면 터미널 탭(process 실행 상태)이 있으며 기능은 폴더 루트와 같음 | 루트 = folder만 허용하는 검사(`tileDoc.go:56`) 완화. 탭 `[파일] [터미널 N]`의 파일 = 장비 디렉토리 |
| 장비-2(여러 개 열기) | 같은 장비 타일을 여러 개 열 수 있고, 타일 규칙대로 부모격 디렉토리(장비 디렉토리 = 장비가 묶인 계정 폴더) 타일에 종속 | 각 타일이 경로를 따로 가짐(해석). 닫기 규칙 등은 폴더 자식 타일과 같게 |
| 장비-3(보드 이동) | 보드 사이를 옮겨 다닐 수 있음 | 폴더 타일의 "새 보드로 분리"·보드 이동과 같게. 미해결 "기본 보드가 아닌 보드에서 새 보드 불가"와 맞물림 |

## 제안한 방식 (사용자 확인 전)
- 목록 = process(bash + `ls`/`dir` 파싱) 대신 **worker REQ 하나**(경로 -> 항목 목록, Go `os.ReadDir`). 이유: 파일 이름 공백·줄바꿈, Windows `dir` 출력이 시스템 언어에 따라 다름, process는 DB·PENDING·복원 절차가 무거움. OS 차이는 Windows 드라이브 목록 정도
- 실행만 기존 process(EXEC, `cwd` = 그 폴더). `processes.node_id`는 NULL 가능 -> 노드 없는 process = R3(경로 없는 process)와 같은 처지
- 서버 타일 문서(`cmd/supervisor/router/tileDoc.go`)가 `folder | terminal`만 검사 -> 새 타입 추가 필요. 프론트 `TerminalTile.nodeId: number` 필수 -> 노드 없는 터미널 타일 처리 필요
