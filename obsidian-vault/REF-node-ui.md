## 배경 — 이전 컨셉 폐기
2026-08-07 확정했던 "배치도(캔버스)=홈 + 트리=보조내비" Phase1-5 컨셉은 **2026-08-10 전면 폐기**. GitHub `ba2slk/termspace`(가로 캔버스 위에 터미널을 나열하는 Electron 워크스페이스 앱) UI가 마음에 든다는 계기로, **화면 전체를 그리드로 나눠 터미널/폴더를 타일로 상시 배치**하는 방향으로 대체. 옛 컨셉 요약은 `history/node-ui.md` 2026-08-07 항목 참조(상세 원문은 git log의 이 파일 이전 버전).

## 큰 그림
- 접속 시 전체화면(메뉴 여부 미정) 기반, 타일 1개(root)로 시작.
- 트리거(버튼 등, 미정) → 타일 분할 → 터미널 또는 폴더(node 카탈로그 리스트/트리 축소판) 추가.
- **레이아웃 모델 = 2D 타일링이지만 깊이 고정(무한 재귀 BSP 아님)**: 루트는 axis(행/열)로 한 번, 그 안에서 반대축으로 한 번 — 최대 2×2. 비대칭(한쪽 밴드만 분할)도 허용(확정 2026-08-10, axis 일반화 2026-08-12). 2026-09-29부터 Grid 구조는 저장하지 않고 타일 순서에서 파생(reflow). **상세 → `REF-node-ui-layout.md` / 화면 크기별 표시 → `REF-node-ui-projection.md`**.

## 구현 방식 — 직접 제작 확정, 외부 라이브러리 안 씀 (2026-08-10, 2026-08-12 재확인)
Splitpanes(단순 split-pane), Golden Layout/Dockview(VSCode류 풀 도킹 엔진) 조사 후 **직접 제작으로 확정**.
- **가장 핵심인 화면 크기별 표시 규칙(당시 짧은축 페이지네이션, 2026-09-29 폐기되고 축별 기준치로 교체)은 어떤 라이브러리에도 없음** — 라이브러리를 쓰든 안 쓰든 이 부분은 100% 직접 구현 필요.
- Golden Layout/Dockview류는 무제한 재귀 중첩+탭+플로팅/팝아웃 창이 기본 전제라, 일부러 채택한 "깊이2 고정" 제약을 오히려 다시 눌러 막아야 함 — 우리가 뺀 자유도를 억지로 되사는 셈.
- 리사이즈 드래그 인터랙션은 Splitpanes 같은 별도 라이브러리 대신 **`DraggableSession`(설계 중, → `REF-util-drag.md`)을 그대로 재사용** — 앱 안에 드래그 처리 체계가 두 개로 갈라지는 것 방지.
- 결론: **Grid/Band/Tile 데이터구조(→ `REF-node-ui-layout.md`) + 렌더링 + 화면 크기별 표시(→ `REF-node-ui-projection.md`)는 직접, 리사이즈 드래그만 DraggableSession 재사용.** 외부 레이아웃 라이브러리 의존성 추가 안 함(2026-08-12 재확인, 결론 불변).

## 기존 인프라 재사용 vs 재작업 매핑
| 기존 요소 | 이 컨셉에서 |
|---|---|
| `ProcessDialog`(전역 다이얼로그, xterm 단일 마운트, → `REF-process-resize.md`) | **재작업 필요** — 팝업이 아니라 그리드 타일에 상시 임베드. store가 "다이얼로그 1개" 가정이면 다중 동시 인스턴스로 리팩터해야 함 |
| node 카탈로그 캔버스/트리(Phase1-5, 폐기) | "폴더" 타일 타입으로 흡수 — 타일 안에 리스트/트리 축소 렌더러(아래 절 재사용) |
| `DraggableSession`(설계만, 미구현, → `REF-util-drag.md`) | **재사용 가능** — 분할 경계 드래그(리사이즈)는 이웃 재정렬 없는 단순 진행형이라 기존 설계와 부합 |
| 공유 리사이즈 관측 그룹(`GroupedSet`, → `REF-util.md`) | **그대로 재사용** — 타일 크기 변경 시 내부 xterm FitAddon 등에 통지 |
| 세션→uid 원장 + 화면복원 ring buffer(설계만, → `REF-process-snapshot.md`) | **확장 필요** — 그리드 레이아웃(위 데이터 구조) 자체도 복원 대상에 포함할지 결정 필요(미정) |

## 폴더 타일 내부 렌더링 — `position_x/y` 폐기, ord 단일 모델로 단순화 (확정, 2026-08-10)
캔버스 홈이 사라지고 "폴더"가 작은 타일 하나로 축소되면서, **`position_x/y`(캔버스 절대배치)는 더 이상 UI에서 안 씀** — 좁은 타일 안에 랙/사무실 물리배치 도면을 재현할 실익이 없어짐(YAGNI, 필요해지면 별도 "물리 배치도" 기능으로 나중에 추가). 항상 `ord` 기반 list/grid 하나만 렌더링. 이원 렌더러(좌표 있으면 그 자리, 없으면 ord)는 **불필요해짐**.
- **DB 컬럼은 유지, 사용만 중단**(2026-08-10 확정) — `position_x/y` 마이그레이션·CHECK 제약은 그대로 두고, 프론트가 안 씀. 스키마 정리(컬럼 drop)는 나중 필요해지면.
- **트리 재배치 드래그의 부수효과**(구현 시 반영 필요, → `REF-node-label.md`):
  1. **device_key 상속이 안 보이게 바뀜**(재귀 CTE로 새 부모 기준 재상속) — 이동 전 확인 UI 권장(미확정).
  2. **선결 조건**: 백엔드 미완성(parentId owner 일치 검증 / 자기 자손 Move 사이클 방지, → `CURRENT.md`)이 이 드래그 UI보다 먼저 필요.
  3. ~~좌표 NULL 폴백~~ — position_x/y 미사용으로 이 문제 자체가 소멸(2026-08-10).
