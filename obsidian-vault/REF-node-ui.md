## 큰 그림
- **홈 = 배치도(캔버스), 트리는 보조 내비**. breadcrumb(현재 경로 가로 나열, 클릭 시 상위 배치도로 이동)=위로 되짚기 / 트리=다른 가지로 점프+검색 — Finder/탐색기 패턴처럼 역할이 안 겹치게 분리.
- `position_x/y`(%) = **실제 물리 배치(랙/사무실 도면) 반영** 예정 + 규모 소규모(수십 개 이내) → 캔버스가 주인공이어도 부담 없음. %는 화면 크기 대응 목적이지만 **상대 배치만 유지될 뿐 절대 간격은 화면폭에 비례해 줄어듦** — 모바일 대응이 별도로 필요한 이유.
- 폴더=다른 구역(하위 배치도) 진입 / 아이콘 상태뱃지=기존 `worker_instances` roster(active/inactive) 재사용 / 더블클릭=기존 `ProcessDialog`(플로팅 터미널) 오픈.

## 리스트/트리 패널 — PC ↔ 모바일 (확정)
- **공통 렌더러 재사용**: "좌표 있으면 그 자리, 없으면 ord 순서 그리드"라는 기존 캔버스 폴백 로직 하나가 — 좌표 없는 노드 자동배치 / PC 리스트·트리 오버레이 / 모바일 리스트 모드 **세 경우 전부**를 커버. 신규 렌더러 불필요.
- **PC**: 캔버스 유지 + **모서리에 리스트/트리를 오버레이 패널로 버튼 토글**(토글 켜면 캔버스와 동시에 보임). 리스트·트리 둘 다 같은 토글 패턴.
- **모바일**: `[ 지도 | 리스트 ]` 세그먼트 토글로 화면 전체를 배타적으로 전환(공간 부족해 동시표시 안 함).
  - **모바일 트리 형태는 미정** — 리스트와 같은 결로 전체화면 검색/점프 시트를 제안했으나 사용자 확인 못 받음. 다음 세션 이어서 결정.

## 트리 재배치 드래그 (확정 — 기능 필요)
- 트리에서 폴더/스크립트를 다른 부모로 드래그 이동 지원.
- **부수효과 2가지, 구현 시 반영 필요**:
  1. **device_key 상속이 안 보이게 바뀜**(재귀 CTE로 새 부모 기준 재상속) — 이동 전 "이제 DeviceB에서 실행됩니다" 류 확인 UI 권장(제안 단계, 미확정).
  2. **좌표 정보 없음**: 트리 드래그는 x/y를 못 정하므로 이동 노드는 `position_x/y=NULL`로 두고 새 부모 캔버스에서 ord 그리드로 폴백(위 공통 렌더러 재사용, 위치는 나중에 캔버스에서 직접 조정).
- **선결 조건**: `CURRENT.md`에 이미 있는 백엔드 미완성 항목(parentId owner 일치 검증 / 자기 자손 Move 사이클 방지)이 이 드래그 UI보다 먼저 구현돼 있어야 함.
