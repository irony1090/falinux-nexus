## 2026-11-02 오후 (2) — steps.json·웹 편집·타일 페이지·파일 보관
- 사용자 "복원도 스크립트 단계로" → `steps.json`을 `deploy`/`rollback` 두 목록 + 단계 종류 `script`/`builtin`(backup·copy·restore)으로 확정. 내장 복원을 `script`로 대체 가능(`BACKUP_DIR`·`NEW_FILES` 제공). 자동 실행 기본 꺼짐(`autoRollback`)
  - 중간에 Claude가 "스크립트로 쓰게 하면 내장 restore는 빠져야 한다"고 잘못 말함 → 사용자 지적, 단계마다 종류를 고르는 것이라 공존
- 사용자 "스크립트·steps.json을 웹에서 직접 작성해 바로 updater에 테스트" → 텍스트 웹 편집 + 바이너리 업로드, 수정 → 저장 → 단계 `실행` → 로그 반복. P1 = 원문 편집 + 검증, `steps.json` 시각 편집 UI는 그다음
- 사용자 "관리자만 접근하는 updater 타일 페이지, 빌드 안에 파일관리(공용·메인키/서브키)·steps.json·스크립트 형제" → 타일 구조 확정(설계-11(배포 정보 타일 열기) 대체). 서브키 파일 계층은 확정, P1은 자리만. 공용은 빌드 안에서 읽기 전용
- 사용자 "서브키에 별칭 등을 적을 수 있게", 파일 보관 방식 질문 → `updaters` 행의 별칭·메모, 파일 = 서버 파일시스템 + DB 메타, 덮어쓰기만(편집 이력 없음)
- 사용자 "잠긴 빌드는 삭제 가능, 빌드 파일 한 번에 받기" → 삭제 규칙(공용은 쓰는 빌드가 있으면 불가)·zip(기본 범위별, 선택 합친 결과). "한 번에 올리기"는 필요 없음
