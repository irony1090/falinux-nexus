## 2026-10-30 — 설계 세션(코드 착수 전)
- 사용자 "업데이트 전용 app 만들자" → BACKLOG의 U1(실행 방식)·U2(대상)·U3(파일 출처)부터 조율
- U1 = **웹 화면 버튼** → 이어서 "supervisor·worker처럼 별도로 도는 앱을 만들고 supervisor에서 파일 업로드·스크립트 실행" 제안 → 곧 "worker로도 다 할 수 있는 것 같다"로 스스로 정리 → 빈 부분만 추림(Job·자가 교체·버전 표시·Linux)
- A안(업데이터 앱) 확정 이유(사용자): "worker들도 여러 장비 것 갈아 줘야 하고 supervisor도 갈아야 한다. 앞으로 배포 버전도 관리되어야 한다"
- 조율: 교체 주체 = 장비마다 `nexus-update` 상주 · 배포 단위 = 장비별 + 전체 일괄 · 버전 관리 = 이력 + 되돌리기 · **Linux 먼저**
- 준비 단계를 사용자가 다시 그림: "node 관리하듯 배포 버전 폴더를 만들고 파일을 채운다. Windows용·Linux용 폴더가 따로" → 업로드 페이지(메인 타일 구성 재사용) + supervisor 보관 + updater가 정해진 위치에 전송·실행
- 폴더 구분: `common` + `<os>-<arch>`, 가안(이름 직접 입력·형식 검사) 확정. 판정은 **파일 유무** — 빈 폴더는 배포 대상 아님(사용자 확인)
- 단계 모델(사용자): "끄기/백업/복사/시작/확인을 각각 스크립트로, 한 스크립트 = 한 단계, 배포 판마다 넣고 개별 실행도 가능" → `steps.json` + 스크립트 파일로 확정. 수동 단계(`manual`)로 정리·로그 수집 같은 도구를 미리 넣어둘 수 있음
- 산출물: 설계안 HTML(`user/배포-설계.html`) · 화면 시안 HTML 3탭(`user/배포-화면.html`). 아티팩트 게시는 API 키 인증 세션이라 막혀 파일로 전달(사용자 인지)
- 화면 시안 반영 확인: 렌더 3장 + 폰 폭(400) 가로 넘침 0, 스크립트 오류 0. 목록 칩 줄바꿈 1건 고침
