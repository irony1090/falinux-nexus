## 2026-08-10(4) — 그리드 UI 구현 방식: 직접 제작 확정 (코드 없음, 조사+설계)
- 계기: "그리드 UI를 직접 만들지, 기존 라이브러리가 있는지" 질문. Vue3 split-pane 라이브러리(Splitpanes 등)와 풀 도킹 엔진(Golden Layout, Dockview)을 웹 검색으로 조사.
- **확정**: 외부 레이아웃 라이브러리 안 씀, 직접 제작. 근거: (1) 가장 핵심인 짧은축 페이지네이션은 어떤 라이브러리에도 없어 라이브러리를 써도 직접구현은 피할 수 없음, (2) Golden Layout/Dockview류는 무제한 중첩+탭+팝아웃이 기본 전제라 일부러 택한 "깊이2 고정" 제약과 상충, (3) 리사이즈 드래그는 이미 설계 중인 `DraggableSession`을 재사용하면 되므로 Splitpanes 같은 별도 드래그 라이브러리도 불필요.
- **2026-08-12 재확인**: 데이터 모델 axis 일반화(→ `history/node-ui-layout.md` 2026-08-12) 논의 중에도 이 결론 그대로 유지.
- 상세 → `REF-node-ui.md` "구현 방식" 절.

## 2026-08-10(3) — `position_x/y` 사용 중단 확정 (코드 없음, 순수 설계)
- 계기: "폴더 타일 안 내용도 absolute 배치 대신 list/grid로 나열해도 되지 않나"는 사용자 제안. 캔버스 홈이 이미 폐기된 마당에 좌표가 필요할 이유도 같이 사라졌다는 논리로 합의.
- **확정**: node UI는 항상 `ord` 기반 list/grid만 렌더링. `position_x/y`는 **DB 컬럼·마이그레이션은 유지하되 값은 안 씀**(컬럼 drop 등 스키마 정리는 나중, YAGNI). 이미 커밋된 DB/CRUD/PatchNode(`9c9d22e`) 코드 자체는 이 세션에서 손대지 않음(코딩은 사용자 직접).
- 부수효과: 이원 렌더러("좌표 있으면 그 자리, 없으면 ord")·"트리 드래그 시 좌표 NULL 폴백" 부수효과가 통째로 소멸 — Phase2였던 "캔버스 좌표 드래그 편집"도 완전히 불필요해짐.
- 상세 → `REF-node-ui.md` "폴더 타일 내부 렌더링" 절 / `REF-node-label.md` position_x/y 항목.

## 2026-08-10 — termspace 영감 그리드로 전면 피벗 (코드 없음, 순수 설계)
- 계기: 사용자가 GitHub `ba2slk/termspace`(가로 캔버스 위에 터미널을 나열하는 Electron 워크스페이스 앱) UI가 마음에 든다며 제시. 조사해보니 라이브러리가 아니라 독립 앱(Linux 전용, 고정폭 칼럼+캔버스 패닝+세션 YAML 저장)이었으나, 컨셉(넓은 캔버스에 터미널 타일 나열)만 차용.
- **큰 방향 확정**: 접속 시 전체화면 기반, 트리거로 타일(터미널 또는 node 폴더) 추가 → 화면을 그리드로 분할.
- **레이아웃 모델 확정**: 처음엔 무한재귀 BSP 타일링(i3/tmux/VSCode류)으로 갈지 1D 가로 스트립(termspace 원형)으로 갈지 갈렸으나, "풀사이즈 화면 기준 열/행 각 최대 2"라는 사용자 제약으로 **깊이 2 고정 그리드**로 수렴(무한재귀 아님). 비대칭 혼합(한쪽 칼럼만 세로분할)도 허용 확정.
- **기존 컨셉과의 관계**: 2026-08-07 확정했던 "배치도(캔버스)=홈+트리=보조내비" Phase1-5 컨셉을 **전면 대체(폐기)** — 별도 화면 공존이 아니라 대체를 사용자가 명시적으로 선택.
- **재사용/재작업 매핑 정리**: `ProcessDialog`(다이얼로그→타일 임베드, 다중 인스턴스 리팩터 필요) / `DraggableSession`(분할 경계 리사이즈에 재사용 가능) / `GroupedSet` 공유 리사이즈 그룹(그대로 재사용) / 세션→uid 원장·ring buffer(그리드 레이아웃도 복원 대상 포함할지는 미정).
- **이월된 구 지식**: 캔버스 폴백 렌더러 로직(좌표 있으면 그 자리, 없으면 ord 그리드)과 트리 드래그 부수효과(device_key 재상속·좌표 NULL)는 UI 파더다임 무관하게 여전히 유효 — "폴더" 타일 내부 구현 시 재사용 예정.
- **미확정으로 이월**: 모바일 캡 형태(1열+세로2단 제안, 미확인) / 분할 UX(버튼메뉴 vs 드래그드롭) / 레이아웃 저장 위치(로컬 vs 서버) / `ProcessDialog` 다중 인스턴스 리팩터 구체 범위 / 라우팅 스킴 재검토.
- 상세는 `REF-node-ui.md`(옛 Phase1-5 절은 이 개정으로 REF에서 제거, 아래 2026-08-07 항목이 유일한 기록).

## 2026-08-07 — node 카탈로그 UI 컨셉 설계 (코드 없음, 순수 논의)
- 사용자가 "core는 얼추 됐는데 UI 컨셉을 어디서부터 잡을지 모르겠다"로 시작한 브레인스토밍. 이미 확정된 데이터 모델(`REF-node-label.md`의 folder=디바이스 컨테이너/script=실행리프, position_x/y=캔버스 절대배치 vs ord=그리드순서 분리)이 사실상 메타포를 가리키고 있어 그걸 그대로 화면으로 옮기는 방향으로 수렴.
- **확정**: 홈=배치도(캔버스, position_x/y가 실제 랙/사무실 물리배치를 반영) + 트리는 보조내비(breadcrumb=위로 되짚기 / 트리=옆 가지로 점프+검색, 역할 분리). PC=캔버스 유지+모서리 리스트·트리 오버레이 버튼토글(동시표시) / 모바일=`[지도|리스트]` 세그먼트 토글(배타적 전환, %좌표라도 절대간격은 화면폭에 비례해 줄어들어 필요). 트리 재배치 드래그 지원(다른 부모로 폴더/스크립트 이동) — 부수효과로 device_key 상속이 안 보이게 바뀌는 문제(확인 UI 권장, 미확정)와 좌표 없음 문제(이동 노드는 position_x/y=NULL로 두고 ord 그리드 폴백 재사용) 발견.
- **미확정으로 이월**: 모바일 트리 화면 형태(전체화면 검색시트 제안했으나 미확인).
- 상세는 `REF-node-ui.md`.
