## 2026-09-29(8) — 전체보기 모드 시안 (코드 없음)
- 사용자 요청: Windows Alt+Tab·Android/iOS 앱 전환처럼 실행 중 프로세스를 한 번에 보는 화면. 상단 버튼으로 진입, **현재 레이아웃 유지**, 많이 보이게, 자유 스크롤(스냅 비활성).
- 시안 "타일링 시안 전체보기"(전부 줄임 시안 기반, 원본·비교 시안은 그대로) 제작: 같은 Grid를 축소 렌더, 역배율 라벨, 타일 누르면 이동, Esc 복귀. 배치 방식(여러 줄/가로 한 줄)과 축소 비율은 토글로 비교하게 둠. 새 예시 "프로세스 많이". → `REF-node-ui-overview.md` "전체보기 모드"
- 이어서 배치 확정: 사용자 "가로와 세로를 비교해서 긴 축 기준으로 grid를 1렬로 나열하고, 짧은 축 기준으로는 가운데 정렬" → 토글 제거, 시안 같은 링크에 갱신(v2).
- 버튼 위치·모양: 사용자 "오른쪽 하단, 색상 포인트, 아이콘도(화면에 따라 둘 다 or 아이콘만)" → 떠 있는 강조색 버튼, 가로 2칸 화면은 아이콘+글자 / 1칸은 아이콘만(v3).
- 위치 재검토: 사용자 "fixed 성질로 하단의 grid1 column 4타일 높이 기준으로 오른쪽 정렬, 크기도 자연스럽게" → Grid 하단 정보 줄 높이의 작은 버튼으로 줄여 그 줄 오른쪽 끝에 고정(v4). 사용자는 위치를 더 고민하겠다고 함.
- 스크롤바 문제: 사용자 "스크롤바 때문에 높이가 틀어진 것 같다, 스크롤 유무에 따라 위치가 달라질 것" → 스크롤바 항상 표시 + 두께 측정(`--sb`)으로 버튼·영역 높이 보정(v5) → 사용자 선택으로 **스크롤바 숨김**으로 교체(v6), `--sb` 보정 제거 → 오해였음: 사용자 뜻은 "필요하면 보이는 auto 성격" → auto 복귀 + 현재 스크롤바 두께 측정(`--sb-h/-w`)으로 버튼 보정(v7).
- 상단 Grid 탭: 사용자 "모바일에서 폭이 부족하면 첫 페이지 … 현재-1 / 현재 / 현재+1 … 끝 페이지" → 넘칠 때만 줄인 탭으로(v8). → `REF-node-ui-overview.md` "헤더 내비게이션"
- 사용자 "PC·폰 둘 다 끝 페이지가 안 나온다" → 헤드리스 크롬으로 재현: 폰 G4에서 한 칸 빈틈 채우기로 7개 전부 그려져 G7 잘림 + PC는 칼럼 표시가 왼쪽 번호만이라 끝에서 `6/7`. 후보를 넓은 것부터 맞춰 보는 방식 + 칼럼 범위 표시 + 동점 뒤쪽 우선으로 수정, 스크롤 0~100% 스윕으로 잘림 없음 확인(v9).
