## 2026-10-12 — 결정 필요 항목 정리 → 종료 정책 확정
- 사용자 "process 결정 필요항목 내용이 뭐야?" → 3항목(EXEC 실행 방식 / 끊긴 장비 kill / kill 에스컬레이션) 현재 동작·선택지 제시 → shebang 설명
- 사용자 결정: EXEC = A 현상 유지 / 끊긴 장비 kill = 기록 후 재접속 때 kill / 정상 종료 신호 먼저, 모든 사용자가 타일을 닫으면 가장 강한 시그널
- 확인 Q&A: 모두 닫음 ≠ 최소화(최소화는 트리에 남음) / 닫은 뒤 다시 열기 = "위치 없음" 행 / "kill 두 번" = 같은 자리에서 두 번째 종료가 강제 종료(확인 창 경유) → 권장 3개(종료 요청 뒤 닫기 허용 · 모두 닫음 = 전 계정 보드에 터미널 타일 없음 · 두 번째 종료 = SIGKILL) "확정"
- 구조안 제시: 종료-1(신호 구분)~종료-6(확인) + KP1(기록 위치)~KP4(동시성 한계) 권장안 → 사용자 "재부팅할테니 vault 정리" — **승인 대기로 세션 종료**

## 2026-10-12(2) — 보기 계정은 "모두 닫음" 판정에서 제외
- 사용자 제기: "보기 권한으로 공유받은 유저는 종료 요청에서 제외해야 하지 않나"
- 확인: 종료 요청 자체는 이미 조작(20) 이상만 가능(kill 인가, 보기 = 403). 빠진 곳 = 강제 종료 조건 ①이 "전 계정 보드"라 보기 계정이 타일만 열어 둬도 SIGKILL이 막힘
- 확정: 판정 대상 = `process_permission >= 20` 계정. 공유 해제·권한 변경(조작 → 보기) 커밋 뒤에도 종료-4(모두 닫음) 판정 실행. 보기 계정 타일은 남고 종료 결과만 보임
- 나머지 구조안(종료-1(신호 구분)~종료-6(확인) · KP1(기록 위치)~KP4(동시성 한계))은 승인 대기
