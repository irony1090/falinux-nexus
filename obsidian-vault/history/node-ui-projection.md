## 2026-09-29(5) — 페이지네이션 폐기 → 좁은 축은 1.0으로 보고 다시 채움 + 채우기 방향 통일 (코드 없음, 시안만)
- 계기: 두 기기 시안에서 사용자가 "양쪽이 동기화 안 되는 것 같다, 처음부터 순서가 다르고 PC 6개인데 폰은 3개"라고 지적.
- 원인 두 가지: ① 폰은 Grid마다 페이지 1쪽만 보여 나머지가 2쪽에 숨음(페이지네이션) ② 칸 읽기 방향이 기기마다 달라(PC 위→아래 / 폰 왼→오) 폰 페이지가 `1,3 / 2,4`로 뒤섞임. 데이터(트리·순서)는 동일했음.
- 사용자: **"페이지네이션은 내가 원한 게 아니다"** → 대안("용량 1칸 축에서는 저장된 0.5를 1.0으로 보고 다시 채우기, 넘치면 다음 Grid로 가로 스크롤") 확인 후 채택. 채우기 방향은 모든 기기 칼럼 우선으로 통일.
- 결과: 기기마다 다른 건 Grid 하나의 칸 수뿐(PC 2열×2행 / 폰 세로 1열×2행). 폰 = G1 `1/2`, G2 `3/4`, G3 `5/6`. headless Chrome으로 두 화면 모두 6개 전부·같은 순서 확인.
- 유틸: `paginate` 삭제, `effectiveSize` 추가, `toGrids(tiles, sizeOf)`로 변경. Grid 하단 "secondary 분리 1 2" 페이지 버튼 제거.
- 상세 → `REF-node-ui-projection.md`(전면 재작성), `REF-node-ui-layout.md` "Grid 배치".

## 2026-09-29(1) — 타일링 시안(아티팩트) + 축별 기준치 페이지네이션 + 칼럼 단위 스냅 (코드 없음)
- 모양을 먼저 보고 싶다는 요청으로 아티팩트 시안 제작: https://claude.ai/artifact/Tz9DeJd2B1Un5hm2GjFyLY (Grid/Band/Tile 모델 그대로, 예시 데이터).
- **발견**: PC 16:10에서 2×2가 한 화면에 2개씩만 보임 — 옛 짧은축 규칙(`width < height` 이분법)이 모든 화면에서 한 축을 항상 페이지로 분리하기 때문. REF 예시1 가로형 표도 같은 결과였음(규칙 자체의 빈틈).
- 첫 제안: "짧은축 ÷ 2 < 최소 타일 크기일 때만 분리". 사용자가 더 단순한 안으로 정리 → **가로/세로를 각각 기준치와 독립 비교, 둘 다 넘으면 4등분**. 옛 규칙의 일반화로 채택, 두 축 다 미달이면 타일 1개=1페이지(상한 4장).
- 시안에 화면 크기 입력·끌어서 조절·기준치 입력 추가 → 사용자가 조절해 **`W_TH=728`, `H_TH=560`** 확정. 측정 대상은 창이 아니라 Grid 영역.
- 판정 로직을 **상태 없는 유틸(`capacity`/`paginate`/`columnStops`)로 분리**하기로 결정 — 시안의 `TileSplit` 블록이 포팅 대상. 실제 코드는 미작성(사용자가 작성 예정).
- **오버플로 Grid 스크롤 = 칼럼(Grid 가로 절반) 단위 마그네틱 스냅** 확정 — 0.5/1.5 같은 Grid 경계 걸친 위치도 허용. 가로 1칸이면 Grid 단위 폴백. 2026-08-19(3)의 Grid 단위 스냅 제안을 대체.
- 상세 → `REF-node-ui-projection.md`(화면 크기별 투영) / `REF-node-ui-impl.md` "① ② 유틸 API"(판정 유틸) / `REF-node-ui-layout.md` "오버플로"(칼럼 단위 스냅).

## 2026-08-10(2) — 화면 크기별 투영: 짧은축 페이지네이션 확정 (코드 없음, 순수 설계)
- 계기: "그리드를 백엔드에 저장하는데 다른 디바이스로 접속하면 풀사이즈캡→모바일캡 전환을 어떻게 할지" 질문에서 시작.
- 처음엔 "캔버스 하나 저장 + 뷰포트별 오버플로 트레이/무제한 스택" 두 안을 제시했으나, 사용자가 "화면비로 짧은 축을 찾아 그 축은 캡=1로 무시" 아이디어를 내며 방향이 바뀜.
- 여러 차례 예시(D형 그리드: 컬럼1=T1 단독, 컬럼2=T2/T3 세로분할)를 세로형/가로형 화면 각각으로 손으로 풀어보며 합의: **짧은 축의 칸들은 페이지로 분리(스와이프), 긴 축은 기존 캡대로 한 페이지에 동시 표시**. 세로형=페이지가 컬럼 단위 / 가로형=페이지가 깊이(depth) 단위. 패킹 규칙(앞 슬롯부터 채우고 원래 ratio 유지, 남는 슬롯은 빈칸)까지 확정.
- 그리드가 2×2 고정이라 페이지도 최대 2장 — 상한이 항상 보장되는 게 이 설계의 핵심 장점.
- 지난 세션 "모바일 캡=1열+세로2단"(임시안, 미확인)은 이 알고리즘으로 대체·일반화되어 폐기.
- 레이아웃 저장은 서버 확정(다른 기기 접속 지원 목적)했으나, 세션 단위 vs 계정 단위는 여전히 미정으로 이월.
- **2026-08-12**: 이 규칙 자체는 컬럼우선 전제였음이 드러나 primary/secondary 구조축 기준으로 일반화됨(위 2026-08-12 항목).
