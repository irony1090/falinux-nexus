## 결정 (SD = 공유-d)
| 결정 | 묻는 것 | 확정(2026-10-07, 제안 그대로) |
|---|---|---|
| SD1(출력 구독 범위) | 보는 보드의 터미널만 출력 구독하나(보드 미리보기 희망안에서 나온 것) | **지금처럼 볼 수 있는 것 전부 구독.** 보드를 바꿀 때마다 구독 해제·재구독 + 스냅샷 재요청이 필요해지고, 미리보기는 미뤘으므로 얻는 것이 없음. 나중에 미리보기를 할 때 다시 봄 |
| SD2(실행 때 터미널 타일을 넣을 계정) | 누가 실행하든 그 터미널을 볼 수 있는 다른 계정 트리에도 넣나(작업공간-e 발견 + SH2 경계 ①) | **넣음: 볼 수 있는 계정 전부.** 실행한 계정 = 지금처럼 요청한 보드. 그 외 계정 = 그 스크립트의 조상 폴더를 보여 주는 폴더 타일이 있는 보드(그 타일 아래), 없으면 기본 보드 루트 끝. SH2 경계 ①(소유자 실행 → 받는 쪽)과 발견(받는 쪽 실행 → 소유자)을 같은 규칙 하나로 처리. 기각: 실행한 계정만(소유자가 자기 폴더에서 돌고 있는 것을 화면에서 볼 길이 없음 — SH9 "폴더 소유자에게 보인다"와 어긋남) |
| SD3(실행 중 터미널 치우기) | SD2로 남의 터미널이 내 트리에 생기면 kill 없이 치울 수 있나 | **닫기 대신 최소화**(내 것·남의 것 모두, 트리에 `minimized` 표시만) + 루트 타일 `[파일] [터미널 N · 최소화 n]` 탭 + 스크립트 행 "실행 중 N · 최소화 n" + kill은 어디서든 확인창(취소 / 종료 / 종료하고 닫기) + 머리 줄 A안 `RUN▾ [최소화\|크기\|×]`. 전문 → `REF-process-share-realtime-ui.md` "SD3 확정 전문" |
| SD4(`SHARE:CHANGE` 토픽) | 받는 쪽 모든 탭에 무엇으로 보내나 | **계정 토픽 `TILES:<userId>` 재사용**(이미 계정 단위 이벤트가 여기로 감, 새 구독 없음). 이름 정리(`USER:`)는 하지 않음 |
| SD5(구독·권한 재계산 방식) | 공유 걸기·풀기·노드 이동·삭제 네 곳에서 구독을 어떻게 맞추나 | **공통 함수 하나**: `reconcileAccess(users, uids)` = 영향받는 계정 × 영향받는 살아 있는 process를 다시 판정 → 볼 수 있으면 그 계정 소켓 구독, 없으면 해제 → 크기 우선권 다시 맞춤(`resyncSizeOwner`) → 단계가 바뀐 계정에 `SHARE:CHANGE`. 영향 계산: 공유 걸기·풀기 = 그 계정 1명 × 그 노드 아래 살아 있는 process / 이동·삭제 = 작업 **전에** 대상 노드와 조상·하위에 공유 행이 있는 계정 × 대상 아래 살아 있는 process. 기각: 경우마다 따로 계산(이동·삭제에서 빠뜨리기 쉬움) |
| SD6(실효 단계 재조회) | `SHARE:CHANGE`를 받은 프론트가 무엇으로 다시 조회하나 | **새 API 없음**: 기존 `GET /processes/lookup`(트리에 있는 uid)·노드 조회(`permission` 포함)를 다시 부름(프론트 query 무효화). 볼 수 없게 된 것은 404/목록에서 빠짐 → 비활성화 |
| SD7(받는 쪽 타일 추가 시점) | 공유를 걸 때 받는 쪽 트리에 언제 무엇을 넣나 | **노드 공유**: 받는 쪽이 그 노드를 못 보다가 보게 될 때(0 → 10 이상)만, 받는 쪽 기본 보드 루트 끝에 폴더 타일. 이미 받는 쪽 어느 트리에 그 노드의 폴더 타일이 있으면 안 넣음. 단계만 바뀌면(10 → 20) 안 넣음. **process 단독 공유**: 같은 조건으로 터미널 타일. **풀 때**: 타일 그대로(공유 사라짐 처리) |
| SD8(받는 쪽 루트 목록) | 받는 쪽이 공유 폴더 타일을 닫으면 다시 열 길이 있나 | **루트 목록에 공유받은 최상위 노드도 넣음**(`GET /nodes` parentId 없음 = 내 루트 + 공유 루트, 응답에 `permission`·소유자 닉네임). 기각: 안 넣음(닫으면 다시 못 엶) |
| SD9(경로 줄 멈춤) | SH2 경계 ② — 받는 쪽 경로를 공유 루트에서 멈추게 | **노드 응답에 `parentVisible`(부모를 볼 수 있나) 추가** → `fetchNodePath`가 false면 멈춤. 기각: 프론트가 404에서 멈춤(진짜 오류와 구분 안 됨) |
