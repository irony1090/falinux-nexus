## SH3(받은 계정 권한) 단계 — 4단계(차단 포함) + 가까운 공유 확정(2026-10-06)
| 단계 | 노드(폴더·스크립트) | process |
|---|---|---|
| 차단 | 안 보임 | 안 보임 |
| 보기 | 목록·내용 읽기 | 출력 보기(크기 고정 + 스크롤) |
| 조작 | 보기 + 실행 | 보기 + 입력 + kill + 크기 우선권 후보 |
| 편집 | 조작 + 추가·이름 변경·내용 수정·삭제·이동·장비 지정 | 조작과 같음 |

- 단계는 순서가 있는 값 하나(`shares.permission`)로 저장 — 나중에 단계를 끼워 넣기 쉬움.
- "조작"을 따로 두는 이유: 터미널 입력은 그 장비에서 아무 명령이나 실행하는 것과 같아서 스크립트 편집보다 권한이 큼.
- **겹칠 때 = 가까운 공유(2026-10-06 확정)**: 같은 계정에 대해 그 노드에서 루트 쪽으로 올라가며 **처음 만나는 공유 행의 단계**를 따름. 사용자 이유: 루트에서 공유해 버리면 그 아래를 감당할 수 없음 — 하위 폴더에 낮은 단계를 걸어 줄일 수 있어야 함. 기각: 높은 단계(권한을 더하기만 해서 줄일 수 없음).
- process 단독 공유(`process_shares`)는 노드보다 가까운 것으로 봄 → 있으면 그 단계가 우선.
- **차단 단계 추가(2026-10-06 확정)**: 단계 = 차단 < 보기 < 조작 < 편집. 차단이 가장 가까운 공유면 그 노드와 아래가 목록·process 모두 안 보임. 차단은 상위 공유를 줄이는 용도라 단독으로 걸면 공유 없음과 같음.

## SH10(노드 복사) — 확정(2026-10-06, 사용자 "그대로 확정")
지금 노드 복사 기능 없음(`query/node*.sql`에 Create/Get/List/Move/Place/Update/Rename/Delete/Patch만).

| 항목 | 제안 |
|---|---|
| 권한 | 원본 = 보기 이상 / 목적지 = 내 트리 또는 편집 단계 공유 폴더 |
| 소유 | 복사본 소유자 = 목적지 소유자(SH8과 같은 규칙), `created_by` = 복사한 사람 |
| 폴더 복사 | 하위 전체 재귀. 받은 쪽에게 차단인 하위는 제외 |
| 장비 지정 | 노드 자신의 `device_key`만 복사(상위에서 상속받던 값은 따라가지 않음) — 상위에서 상속받던 스크립트를 내 트리로 복사하면 장비 미지정이 되어 다시 지정해야 함(남의 장비를 끌고 오지 않음) |
| process | 복사하지 않음 |
| 시점 | 공유 작업 단위 안(권한 판정 공유). 내 트리 안 복사도 같은 API |

**클립보드 표시(2026-10-06 확정, 사용자 의도: 붙여 넣기 전 "내가 복사한 노드가 무엇인지" 보이게)** — 프론트 상태만, DB 변경 없음
| 항목 | 내용 |
|---|---|
| 담는 것 | 복사한 노드의 id·이름·종류만(1depth — 하위는 펼치지 않음) |
| 표시 | 클립보드에 든 노드 행을 모든 폴더 타일에서 흐리게 + "복사됨 N개: a, b, c" 줄과 비우기 버튼. 복사도 표시함(윈도우 탐색기는 잘라내기만 흐리게 함) |
| 범위 | 같은 브라우저 탭끼리(`localStorage`), 기기 간 공유 없음 |
| 붙여넣기 | 그때 서버가 권한 재확인(복사 뒤 공유 단계가 바뀌었을 수 있음). 붙여 넣은 뒤에도 클립보드 유지 |
| 복사 결과(부가, 있으면 좋음) | 붙여넣기 응답 = 만든 노드 목록 + "볼 수 없는 하위 N개 제외"를 짧게 알림 |
| 미정 | 잘라내기(붙여 넣으면 이동, 이동 API는 이미 있음)를 같은 클립보드에 넣을지 — 넣으면 복사와 표시를 구분해야 함 |
