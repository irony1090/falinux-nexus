## 식별 단위
| 단위 | 같은 값이 되는 조건 | 예 |
|---|---|---|
| 탭 id | 같은 탭 | 크롬 탭 1·탭 2는 다름 |
| sid | 같은 브라우저 + 같은 로그인 | 크롬 탭 1·2는 같은 sid. 엣지에서 같은 계정 로그인 = 다른 sid. 재로그인 = 새 sid |
| 계정(user_id) | 같은 계정 | 크롬·엣지·폰의 같은 계정 |

탭 id ⊂ sid ⊂ 계정. sid 하나는 계정 하나에만 속함. sid = 세션 쿠키 원본값이라 다른 세션에 보내면 안 됨.

## 결정 O~V (번호는 `REF-node-ui-terminal.md` J~N에 이어서)
| 결정 | 내용 |
|---|---|
| O(계정 동기화) | 같은 계정이면 탭·브라우저·기기와 관계없이 같은 process를 봄. 지금 구독은 sid 단위라 같은 브라우저까지만 감 |
| P(공유 권한) | 공유 신청은 그 process의 소유 계정만 |
| Q(크기 우선권 단위) | 서버가 발급하는 **탭 id** 단위. 실행한 탭 1순위, 이후 그 계정의 연결된 탭 중 먼저 연결된 순서. M(크기 우선권)의 나머지 규칙(60초 대기·되찾지 않음·비소유자 고정+스크롤·403·당사자 소켓에만 알림)은 그대로 |
| R(공유 대상 단위) | 계정 단위. 공유받은 계정도 O처럼 그 계정의 모든 탭이 동기화 |
| S(구독 역할 분리) | 인가 = **계정**(DB: `processes.owner_user_id`, 나중에 공유 테이블) / 출력 라우팅 = **탭(소켓 연결)**(메모리 Hub, 이미 연결 단위) / 크기 우선권 순서 = **탭 id**(메모리). 탭 id는 DB에 저장하지 않음(닫힌 탭의 죽은 행만 쌓이고, O에선 같은 계정 탭이 모두 보므로 정보가 없음) → **`process_subscribers` 제거**. 그 역할(소켓 재연결 시 재구독·구독 목록 조회)은 "계정이 볼 수 있는 살아 있는 process" 조회로 대체 |
| T(공유 자식 상속) | **볼 때 확인**: 자식 process에는 공유 행을 넣지 않고, 확인할 때 `parent_uid`를 따라 올라가며 공유 행을 찾음(PostgreSQL `WITH RECURSIVE` 한 번). 공유 취소 = 행 하나 삭제로 자손 전부 즉시 차단. 확인 시점은 소켓 연결·구독 때뿐(라우팅은 메모리). 기각: 실행할 때 복사(권한이 여러 행에 흩어져 취소 누락 위험) |
| U(목록 API) | `GET /processes/subscriptions`(sid 구독 목록) → **`GET /processes`**(그 계정의 살아 있는 process, 요청 탭 기준 `sizeOwner` 포함) |
| V(탭 id 전달) | 소켓 연결 직후 서버가 **`TAB:ID` 이벤트**를 먼저 보냄. 기각: 프론트가 연결 후 `call`로 요청(왕복 1회 추가 + 대기 처리 필요) |

전부 사용자 확정(2026-10-01).

## 탭 id 수명
| 무엇 | 어디에 | 하는 일 |
|---|---|---|
| 탭 id 보관 | 브라우저 `sessionStorage` | 새로고침해도 같은 id를 다시 내밀 수 있게. 탭 닫으면 지워짐. 만료 시간 없음 |
| 60초 대기 | 서버 메모리 | 그 탭의 소켓이 끊기면 탭 id와 크기 우선권을 60초 보관 |
| 판정 | 서버 | 60초 안에 같은 id로 재연결 = 같은 탭(우선권 유지). 넘으면 다음 탭으로 넘기고 id 폐기 |

- `sessionStorage`는 탭 × 출처 단위. **복사·복원되는 경우**: 크롬 "탭 복제", opener가 있는 `window.open`, 닫은 탭 다시 열기·세션 복원 → 서버가 "같은 sid + 지금 다른 소켓이 안 쓰는 id"일 때만 재사용하고 아니면 새로 발급해서 해결.
- **한계**: 서버는 끊긴 이유가 새로고침인지 탭 닫기인지 모름 → 탭을 닫아도 60초 동안은 넘어가지 않음.
- `localStorage`는 같은 출처의 모든 탭이 공유하므로 탭 id 보관에 쓰면 안 됨.

## 진행 순서 (각 단계도 구조 합의 → 코드)
| 단계 | 내용 | 선행 |
|---|---|---|
| 1 | **탭 id + S(구독 역할 분리)** 백엔드·프론트 한 번에 (아래 "1단계 구조") | 없음(현재 미커밋 코드 위) |
| 2 | supervisor 재기동 → 실행·출력·kill·크기·탭 2개 사이 우선권 넘김 확인 → 커밋 | 1 |
| 3 | ⑪ 타일 트리 서버 저장(테이블/API) — 구조·결정 → `REF-node-ui-save.md` | 2 이후 권장 |
| 4 | O(계정 동기화) 화면: 다른 탭·기기가 저장된 트리를 불러와 표시 + 트리 변경 실시간 반영 | 1·3 |
| 5 | 공유 P·R·T: `process_shares`, `processes.parent_uid`, 폴더 process DB 영속 | 1·4 |

- 1에서 탭 id와 S를 묶는 이유: 크기 우선권의 다음 후보는 구독 구조가 정함(지금 DB sid 목록 → S 후 계정의 연결된 탭). 따로 하면 후보 목록을 두 번 고침. 고치는 파일도 같음(`subscribe.go`·`sizeOwner.go`·`processApi.go`).
- 2026-10-01 미커밋 코드: sid 단위 크기 우선권(`sizeOwner.go` 등)은 1에서 대부분 바뀌므로 따로 확인·커밋하지 않고 2에서 한 번에. 터미널 임베드(J·K·L·N)는 그대로 사용.
- O는 ⑪ 없이는 화면에 안 보임: 다른 탭이 데이터를 받아도 그 탭의 타일 트리(브라우저 메모리)에 놓을 자리가 없음.
