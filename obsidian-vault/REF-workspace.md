## 확정 (2026-10-06, 사용자)
| 항목 | 내용 |
|---|---|
| 작업 공간 | 계정당 타일 트리 여러 개. **각 작업 공간의 첫 타일 = 루트 폴더**(지금 루트 규칙과 같음) |
| 만들기 | 기본 작업 공간 `/`의 **폴더 타일**에서 "새 작업 공간" 버튼 → 그 폴더 타일 + 하위가 새 작업 공간으로 옮겨감(그 폴더가 새 루트). 이름 지정, 안 하면 기본 이름. 루트 폴더 타일에는 버튼 없음(옮기면 원래 작업 공간이 빔) |
| 단계 | **`/`에서만 만듦** — 새 작업 공간 안에서 또 만들기 금지 → 1단계 평면(`/` 아래 나란히). 이유: 중첩은 너무 복잡 |
| URL | 기본 = `/`(지금 그대로, 계정마다 자기 것) / 새 작업 공간 = `/w/{hash}`. 기각: `/{hash}`(`/login`과 충돌) |
| 헤더 | `AppHead.vue`의 닉네임 자리에 작업 공간 이름 |
| 이동 단위 | **폴더 단위만 강제** — 터미널 단독으로 다른 작업 공간 이동 불가 |
| W1(분리 범위) | **가. 타일 트리 하위.** 원칙 = **터미널은 실행 버튼을 누른 타일의 것**: 다른 폴더로 들어간 타일에서 켠 것은 그 타일 것, 닫기로 옮겨진(`adopted`) 것은 옮겨 간 타일 것. 기각: 나. 노드 하위(스크립트 위치로 소유 판정) |
| W2(삭제 처리) | **`/` 루트 끝으로 되돌림** — 실행 중 터미널 포함, kill 없음. 공유가 사라져 비활성화된 작업 공간은 되돌릴 것 없이 닫음 |
| W3(이동 범위) | **제한 없음**(`/`↔새 작업 공간, 새 작업 공간끼리). 대상 작업 공간 루트 끝에 붙음. 작업 공간의 루트 폴더 자체는 이동 불가(→ W2(삭제 처리)로). ※ 타일 이동이며 노드 이동(`parent_id`)·SH10(노드 복사)과 별개 |
| 터미널 머리 줄 | **일반·공유 모든 터미널 타일**(사용자 재확인 2026-10-06): **`[실행한 타일 위치 번호] 실행된 경로 / 이름`** (예: `[2] 장비A / build.sh`). 번호 = 소유(타일 트리), 경로 = 스크립트가 있는 폴더(노드 트리). 지금 `← opener`(연 타일의 **현재** 노드 이름 — 닫기·폴더 이동 뒤 엉뚱한 이름)를 대체. 공유받은 것은 경로를 공유 루트부터(`kim / 장비B / ...`). 번호는 화면 배치가 바뀌면 함께 바뀜 |
| 루트 타일 이동 | **제한 없음**(2026-10-06, 사용자 "제한을 걸어야 될 이유가 있나") — 작업 공간의 루트 타일도 지금처럼 상위·다른 폴더로 이동 가능. 깨지는 것 없음: 분리는 타일을 옮길 뿐이고 소유는 타일 트리, 권한은 노드. 기본 이름은 만들 때 정해지고 이동을 따라가지 않음(바꾸려면 이름 변경). 기각: 루트 타일만 제한 / 작업 공간 전체 제한(W3(이동 범위)과 충돌). ※ 공유받은 폴더의 경로 줄이 공유 루트에서 멈추는 것(SH2 경계 ②)은 UI 제한이 아니라 권한 결과 — 그대로 |
| 권한과의 관계 | 권한 = 노드(SH1(공유 단위), 가까운 공유) / 배치·소유 = 타일 트리. 둘이 어긋나도 됨 |

## 코드 영향 (트리 하나 가정이 들어간 자리)
| 자리 | 지금 | 바꿀 것 |
|---|---|---|
| `tile_trees` | PK `user_id` | `tree_id` PK + `user_id` FK + 이름·순서·hash |
| `GET/PUT /tiles` | 트리 id 없음 | `/tiles/:treeId` + 목록·생성(분리)·삭제(W2)·폴더 이동(W3) |
| version | 계정에 하나 | 트리마다(⑪-2(충돌 처리) 규칙 그대로) |
| `TILES:<userID>` 토픽 | 계정 단위 | 이벤트에 `treeId` |
| exec 타일 추가(`appendTerminalTile`) | 부모 없으면 루트 끝 | 요청에 `treeId`, 부모 없으면 **그 작업 공간** 루트 끝 |
| **고아 안전망(3-d)** | 지금 트리만 확인 | **계정의 모든 트리 확인**(안 하면 다른 트리에 중복으로 붙음). 타일이 모든 트리에서 사라진 경우 대비 exec 때 `processes`에 트리 id 기록 추천 |
| 서버 트리 검사 | 트리 하나 안에서 | uid는 계정 전체 트리에서 하나만 |
| 크기 우선권 후보 | 계정의 탭 | 그 작업 공간을 보고 있는 탭 |
| `tileTree.store` | 트리 하나 | 지금 보는 트리 전환(인스턴스 여러 개 불필요) |

## 작업 단위 초안 (공유-a·b·c 다음, 공유-d 전 — 순서 C(끼워 넣기), `REF-process-share.md` "작업 단위 · 순서")
| 작업 단위 | 내용 |
|---|---|
| 작업공간-a(DB) | `tile_trees` → `tree_id` PK + `user_id` FK + 이름·`hash`·순서·기본 여부. 기존 행 = 각 계정의 `/`. `processes`에 트리 id(고아 안전망용) |
| 작업공간-b(API) | `/tiles/:treeId` GET/PUT(트리별 version) + 목록 · 만들기(분리, W1(분리 범위)) · 삭제(W2(삭제 처리)) · 폴더 이동(W3(이동 범위)). `TILES:` 이벤트에 `treeId` |
| 작업공간-c(exec·안전망) | `appendTerminalTile`에 `treeId` + 부모 없으면 그 작업 공간 루트 / 고아 안전망 = 모든 트리 확인 / uid 계정 전체에서 하나 / 크기 우선권 후보 = 그 작업 공간을 보는 탭 |
| 작업공간-d(프론트) | 라우트 `/`·`/w/:hash` + `tileTree.store` 트리 전환 + "새 작업 공간" 버튼(`/`의 폴더 타일, 루트 제외) + 헤더 이름 + **터미널 머리 줄 `[실행한 타일 번호] 경로 / 이름`** |
| 작업공간-e(확인) | 분리·삭제·이동·URL 직접 접속·탭 2개에서 다른 작업 공간·고아 안전망 |

## 희망안 (가능하면)
- **`/` 루트 타일 안에 다른 작업 공간 미리보기**: 카드(이름·상태 pill·활동 점), 누르면 `/w/{hash}`. 상태 변화는 지금 계정 구독으로 이미 모든 탭에 옴. 출력 변화는 "출력 구독 범위" 결정 필요 — 제안: 보는 작업 공간만 출력 구독 + 나머지는 묶은 활동 신호. 폴더 내용 변화는 `NODE:` 동적 구독(CURRENT 열린 질문 4)에 걸림
