# REF — node 카탈로그 화면 크기별 표시 (축별 기준치 + 좁은 축 1.0 취급)

> `REF-node-ui-layout.md`에서 분할(2026-09-29) — 같은 트리를 화면 크기에 맞춰 보여주는 규칙만 분리(판정 유틸 코드 → `REF-node-ui-impl.md`). 타일 순서·Grid 채우기·오버플로·스냅은 `REF-node-ui-layout.md`. 이력 → `history/node-ui-projection.md`. 현재 진행 → `CURRENT.md`.

## 전제
- 서버에 저장하는 건 **여는 관계 트리**(타일 크기 포함, → `REF-node-ui-layout.md` "저장 모델")뿐이다. Grid는 매 렌더 파생된다.
- 디바이스별 별도 저장 없음(단일 소스, 화면 크기는 렌더링 시점 관심사).

## 규칙 (확정 2026-09-29)
1. **측정 대상 = Grid 영역**(헤더·여백·Grid 하단줄 제외, 실제 타일 공간). 창 크기 아님 — `useResizeCallback`으로 재는 값.
2. **축별 용량(capacity)**: `가로 ≥ W_TH`면 가로 2칸, 아니면 1칸 / `세로 ≥ H_TH`면 세로 2칸, 아니면 1칸. **기준치 `W_TH = 728px`, `H_TH = 560px`**.
3. **용량 1칸인 축에서는 저장된 0.5를 그 화면에서만 1.0으로 본다**(저장값은 안 바꿈). 그 크기로 순서대로 다시 채우고, 넘치는 타일은 다음 Grid로 → Grid 가로 스크롤(칼럼 스냅)로 이어 본다. **숨겨지는 타일 없음.**
4. 결과적으로 기기마다 달라지는 건 **Grid 하나에 들어가는 칸 수**뿐이다:

| 가로 | 세로 | Grid 한 개 | 예 (기본 기준치) |
|---|---|---|---|
| 2칸 | 2칸 | 2열 × 2행 | 데스크톱 1440×900 |
| 1칸 | 2칸 | 1열 × 2행 | 폰 세로 390×844 |
| 2칸 | 1칸 | 2열 × 1행 | 폰 가로 844×390 → Grid 영역 높이 316 |
| 1칸 | 1칸 | 1칸 | 아주 작은 창 |

예 (0.5×0.5 타일 6개): PC = G1 `1,2 | 3,4`, G2 `5,6 | 빈칸` / 폰 세로 = G1 `1 / 2`, G2 `3 / 4`, G3 `5 / 6`. 순서는 두 기기에서 같다.

- 그 화면의 크기 조절 UI에선 용량 1칸 축의 0.5 버튼이 비활성(안내: "이 화면에선 1.0으로 보임"), 크기 버튼에 `=1×.5`처럼 실제 표시 크기를 덧붙인다(시안).

## 폐기된 규칙
