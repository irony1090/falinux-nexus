## 단계 개별 실행 (10-30 확정, 11-02 보강)
| 항목 | 규칙 |
|---|---|
| `실행` 버튼 | **모든 단계 행**(`manual` 포함) — 실패한 단계만 손으로 다시 돌리는 데 씀 |
| 잠금 판정 | 개별 실행 성공은 **"배포 성공"에 넣지 않음**. 잠금 판정은 배포 1회가 끝까지 성공한 기록으로만 |
| 기록 | `update_step_runs`에 별도 행(인스턴스·단계·결과·시각) → 이력에 "수동 copy"처럼 표시 |
| 순서 | **막지 않음** — 어떤 단계든 단독 실행 가능(`backup` 없이 `copy` 단독이면 로그에 경고) |
| 전송 | 개별 실행 때 바뀐 파일만 먼저 updater에 보냄(sha 비교) |
| 설치본 | 개별 실행은 설치본 이름을 바꾸지 않음 |

## 잠금 (11-02 개정: 빌드 단위 · `잠그기`를 사람이 누름)
| 항목 | 결정 |
|---|---|
| 단위 | `<메인키>/<버전>` 빌드 하나 + 그 빌드가 쓰는 공용 묶음 버전 |
| 동작 | **`잠그기` 버튼을 사람이 직접 누름**(Run·Log 타일). 기록 = `update_locks`(누가·언제·잠글 때 sha), 해제 없음 |
| 조건 | **현재 폴더 sha와 같은 성공 기록**이 있어야 잠글 수 있음. 수정 후 성공 기록이 없으면 비활성 |
| 성공 판정 | 그 메인키 인스턴스 중 **한 대라도** 성공하면 성공 |
| 테스트 배포 | 안 잠금. 몇 번을 해도 됨 |
| 공용 묶음 | 빌드를 잠글 때 쓰는 공용 묶음마다 잠금 행을 같이 넣음(sha 유지) |
| 잠긴 뒤 | 파일·이름 **수정 불가**, 배포는 계속 가능, **삭제는 가능**, 설명 글 수정 가능 |
| 잠그기 전 | 언제든 수정 가능(덮어쓰기, 편집 이력 없음). 수정할 때마다 sha가 바뀜 |
- 잠금 판정은 **DB 함수 한 곳**(공유 판정과 같은 방식). 판정에 개별 실행은 안 들어감

## 삭제 (11-02 신설)
| 대상 | 규칙 |
|---|---|
| 빌드 | 잠겨도 삭제 가능(페이지 안 확인 창). 서버 파일·재배포는 없어지고, 배포 이력(이름·sha 사본)은 남음, updater의 백업·설치본은 영향 없음(복원 가능) |
| 공용 묶음 | 쓰는 빌드가 하나라도 남아 있으면 삭제 불가(`update_uses`). 쓰는 빌드가 없으면 잠겨 있어도 삭제 가능 |

## 되돌리기 (11-02 개정: 복원도 `steps.json`의 단계)
| 겹 | 무엇 |
|---|---|
| 단계 | 스크립트는 일만 하고 실패하면 비정상 종료 코드. **스크립트가 `trap`으로 자기를 되돌리지 않음**(dash·busybox는 SIGTERM에 `EXIT` trap이 안 돎) |
| 전체 | `rollback` 목록 실행(되돌리기 버튼). 기본은 내장 `restore`(백업 복원 + 새로 만든 파일만 삭제). 자동 실행은 기본 꺼짐(`autoRollback`) |
- 백업이 있으면 복원이 우선(실제로 깔렸던 이전 내용). 3회 보존 밖이면 이전 빌드 재배포 — 그때 sha가 다르면 경고, 삭제된 빌드는 재배포 불가
- 스크립트 단계 실패·timeout: 프로세스 트리 종료 → 배포 실패 표시 → 되돌리기 버튼 제안
- `builtin`은 셸을 거치지 않아 Linux·Windows 같은 코드(`robocopy` 종료코드 1~7 함정 없음). Windows에서 다른 건 `script` 단계의 스크립트 종류(`.ps1`)와 프로세스 트리 종료
- supervisor DB 되돌리기 = updater 범위 밖, 빌드 작성자가 스크립트로(설계-8(supervisor 되돌리기) → `REF-update-deploy.md` "대상의 의존성"). 자기 교체 = 확정(설계-10(자기 교체) → `REF-update-deploy.md` "자기 교체")
- **되돌리기 순서 = 안 A(최신만 되돌리기)(11-04 사용자 확정)**: 되돌리기 = "그 배포를 취소 = 배포 직전 상태로"(그 버전으로 가는 게 아님). 백업은 배포마다 쌓이고 `restore`는 디스크가 "그 배포 직후"라고 가정 -> 인스턴스마다 **아직 되돌리지 않은 가장 나중 배포만** 되돌림(`rollback_result <> 'ok'`의 MAX id, 쿼리 `LatestLiveDeploymentID`). 이미 되돌린 배포(`ok`)도 거절, `fail`·`cancel`은 다시 시도 가능. 서버 `rollbackBlock`(`router/updaterDeploy.go`) 한 곳 -> `updRollback` 409 + 상세 `rollbackBlock` 필드 -> `UpdRunTile` 버튼 비활성·안내 줄. 특정 버전으로 가기 = 그 빌드 재배포. 계기 = 11-04 흰 화면(d3이 깔린 채 d2 되돌림 → `CURRENT.md`). 손으로 바꾼 파일은 updater가 모름 = 운영 규칙(updater 대상은 손으로 바꾸지 않음)
- 기각한 안: 단계별 rollback 파일 짝(`00-stop.rollback.sh`) · 한 스크립트 + `STAGE=rollback` 분기 · 스크립트 `trap` 자기 되돌림(신호 문제)

## 버전 표시 (11-02 개정)
- **설치본 이름** = updater가 `state.json`에 "마지막으로 끝까지 성공한 배포의 버전 이름"으로 기록(백업과 같은 곳), 접속 때 supervisor에 보고
- 갱신 = 배포 성공 때만. 개별 실행은 안 바꿈. 백업 복원은 복원한 시점의 이름으로 돌아감
- "실행 중 빌드와 비교"·`RegisterRequest.Build`·`//go:embed env` 방식은 이 파트에서 **쓰지 않음**(필요해지면 `BACKLOG.md` "worker·supervisor 실행 중 빌드 표시")
