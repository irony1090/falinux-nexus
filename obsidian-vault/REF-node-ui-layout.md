## 저장 모델 — 여는 관계 트리 (확정 2026-09-29)
서버(**계정 단위**, 2026-08-19 확정 유지)에 저장하는 main은 **Grid 구조가 아니라 타일 트리**다.

| 필드 | 뜻 |
|---|---|
| `type` | `'folder'` \| `'terminal'` |
| `node` | 폴더 타일은 현재 보고 있는 노드, 터미널 타일은 실행한 노드(+ process `uid`) |
| `parent` | **이 타일을 연 폴더 타일**(노드 트리의 부모가 아님). 루트 = 기본 폴더 타일, 닫기 불가 |
| `kids` | 이 폴더 타일이 연 타일들, 연 순서대로 |
| `size` | `{w, h}`, 각각 0.5 또는 1.0 (아래 "Grid 배치") |
| `adopted` | 터미널 전용, 선택. 폴더를 닫아 부모가 **넘겨받은** 터미널 표시(한 번 붙으면 해제 안 함, 아래 "타일 닫기") |

- 폴더 타일 안에서 다른 폴더로 이동한 뒤 실행해도 부모는 **그 타일**이다.
- Grid/Band/axis는 저장하지 않는다 — 매 렌더 이 트리에서 파생.

## 타일 순서 규칙 (확정 2026-09-29)
**폴더 → 그 폴더가 직접 실행한 프로세스(실행 순) → 넘겨받은 프로세스(`adopted`, 넘겨받은 순) → 그 폴더가 연 하위 폴더(연 순, 각각 재귀).** 트리 깊이 우선 순회에서 프로세스를 하위 폴더보다 먼저 두는 것과 같다. 넘겨받은 묶음은 2026-09-29 추가(아래 "타일 닫기").

| 동작 | 결과 순서 |
|---|---|
| 기본에서 A 열기 | 기본 / A |
| 기본에서 sup(1) 실행 | 기본 / **sup(1)** / A |
| 기본에서 sup(2) 실행 | 기본 / sup(1) / **sup(2)** / A |
| 기본에서 2F 열기 | 기본 / sup(1) / sup(2) / A / **2F** |
| A에서 htop 실행 | 기본 / sup(1) / sup(2) / A / **htop** / 2F |
| A에서 X 열기 | 기본 / sup(1) / sup(2) / A / htop / **X** / 2F (A 묶음 끝, 2F보다 앞) |

- **폴더 열기 UX = 둘 다 지원**: 폴더 이름 클릭 = 그 타일 안에서 이동 / 별도 버튼("새 타일") = 새 폴더 타일로 열기(순서 규칙에 들어감).
- 같은 노드를 여러 번 실행하면 순서대로 `(1)`, `(2)` 표기(시안).

## Grid 배치 — 전체 재배치(reflow) (확정 2026-09-29)
- **타일 크기(2026-09-29(3) 확정)**: 각 타일은 가로·세로를 각각 **0.5 / 1.0** 중에서 고른다(Grid 대비 비율). Grid = 2×2칸이고 0.5×0.5=1칸, 1×0.5·0.5×1=2칸, 1×1=4칸을 차지한다.
  - **새 타일 = 그 화면의 최소 단위**: 축별 용량(→ `REF-node-ui-projection.md`)이 2칸인 축은 0.5, 1칸인 축은 1.0. PC면 0.5×0.5, 폰 세로면 1.0×0.5.
  - **조절 UI**: 타일 헤더의 크기 버튼(현재 크기 표시) → 안에서 가로/세로 0.5·1.0 선택. 그 화면에서 용량이 1칸인 축은 0.5 버튼이 비활성(다른 기기에서 고른 0.5는 그대로 저장되고, 이 화면에선 1.0으로 보고 다시 채움 → `REF-node-ui-projection.md`).
  - 크기는 여는 관계 트리의 타일 필드로 저장(`size: {w, h}`).
- **채우기 = 순서대로 2×2칸에 넣기(reflow)**: 순서 리스트의 타일을 차례로 현재 Grid의 빈 자리에 넣는다. **안 들어가면 그 타일부터 다음 Grid**로 가고 **이전 Grid로는 돌아가지 않는다**(순서 유지, 앞 Grid 빈칸은 빈칸으로 남음). 같은 Grid 안에서는 앞쪽 빈칸도 채운다(시안 가정 — **⑧(같은 Grid 앞쪽 빈칸 채우기) 재검토 중, 아래 "같은 Grid 안 순서 역전"**).
  - **같은 Grid 안 순서 역전 (2026-09-29 사용자 테스트로 발견, 결정 대기)**: `기본, sup(1), sup(2), Rack A`에서 sup(1)을 세로 1.0으로 바꾸면 sup(1)은 왼쪽 아래에 못 들어가 오른쪽 칼럼으로 가고, sup(2)가 비어 있던 왼쪽 아래를 채워 **sup(2)가 sup(1)보다 앞에 보임**. 사용자 기대 = "순서는 무조건 유지, 빈 공간이 나올 수밖에 없는 곳은 빈 공간".
    | 배치 | 왼쪽 칼럼 | 오른쪽 칼럼 | 다음 Grid |
    |---|---|---|---|
    | 현재(앞쪽 빈칸 채움) | 기본 / sup(2) | sup(1) 세로 1.0 | Rack A |
    | 수정안(앞으로만 채움) | 기본 / 빈칸 | sup(1) 세로 1.0 | sup(2), Rack A |
    - **수정안 = 커서**: 각 타일은 **앞 타일의 시작 칸보다 뒤(칼럼 우선 읽기 순서)** 에서만 자리를 찾고, 없으면 다음 Grid. 건너뛴 칸은 빈칸. 기존 예 "가로바 A → htop \| 2F"는 결과 동일.
    - **남은 하위 질문**: 1×1 A → 가로 1.0 바 B → 1×1 C 순이면 B는 아랫줄, C는 A 옆 윗칸(`A | C` / `B`) — 칼럼 우선 순서로는 맞지만 줄 단위로 읽으면 C가 B보다 앞. 이 경우도 C를 다음 Grid로 보낼지(더 엄격한 규칙 필요) 미정.
  - 칸을 찾는 방향 = **모든 기기에서 위→아래, 다음 칼럼**(칼럼 우선). 2026-09-29(4)까지는 기기 axis(세로형은 왼→오)였으나, 기기마다 채운 구조가 달라져 순서가 뒤섞이는 문제로 통일(2026-09-29(5)).
  - 빈칸은 빈 슬롯으로 표시, 통째로 빈 Band는 빈 슬롯 하나.
- **Band 방향 = 배치 결과로 결정**: 2×2칸 배치는 항상 Band 두 개로 나뉜다. 두 칼럼을 가로지르는 타일(가로 1.0)이 있으면 row, 두 행을 가로지르는 타일(세로 1.0)이 있으면 column, 둘 다 없으면 column, 1×1 타일 하나면 Band 1개. 예: 1.0×0.5 가로바 + 0.5×0.5 두 개 → row. 기기와 무관(그 화면의 표시 크기 기준).

| 예 (PC, 2열×2행) | 채운 결과 |
|---|---|
| 0.5×0.5 여섯 개 | G1: 1,2 \| 3,4 / G2: 5,6 \| 빈칸 |
| 기본 0.5×1, sup 0.5×0.5 둘, A 1×0.5, htop·2F 0.5×0.5 | G1: 기본 \| sup,sup (column) / G2: A 위 가로바, htop \| 2F 아래 (row) |

- 파생되는 런타임 구조(저장 안 함):
```
Grid        { axis: 'row' | 'column' | null, bands }  axis = from packing
  Band      { tiles }                                  max 2 per Grid
    Tile    -> opener-tree tile, or null (empty cell)  max 2 per Band
```
- 좁은 화면에서 쓰는 표시 크기(용량 1칸 축은 1.0) → `REF-node-ui-projection.md`. 페이지네이션은 없음(2026-09-29 폐기).

## 타일 닫기 (확정 2026-09-29, ⑩)
- 터미널 타일: 트리에서 제거 → reflow.
- 폴더 타일: 그 폴더가 연 타일들을 부모 소속으로 바꾼다. 기본 폴더는 닫을 수 없음.
  - **하위 폴더** = 닫힌 폴더의 자리(부모 `kids` 안 위치)로.
  - **터미널** = `adopted` 표시 + 부모 `kids` 끝에 붙임(닫힌 폴더 안에서 보이던 순서 유지) → 순서 규칙상 **부모가 직접 실행한 프로세스 뒤**. 이후 부모가 새로 실행해도 그 새 프로세스가 넘겨받은 것보다 앞(사용자 요청 2026-09-29).

| 닫기 전 → 동작 | 결과 (`*` = 넘겨받음) |
|---|---|
| `root / sup1 / sup2 / A / htop / X / serial / 2F` → X 닫기 | `root / sup1 / sup2 / A / htop / serial* / 2F` |
| → A 닫기 | `root / sup1 / sup2 / htop* / serial* / 2F` |
| → root가 sup3 실행 | `root / sup1 / sup2 / sup3 / htop* / serial* / 2F` |
| `root / B / A / htop`(root가 B, A 순으로 엶) → A 닫기 | `root / htop* / B` — 프로세스 → 하위 폴더 규칙상 B보다 앞은 불가피 |

  - 폐기: 최초 구현(2026-09-29(12)) "kids를 닫힌 자리에 통째로 끼움" — 넘겨받은 프로세스가 부모 자신의 프로세스보다 앞으로 옴(`root / htop / sup1 / sup2`).
- 실행 중 터미널은 닫기 비활성(kill 먼저) — 결정 A(닫기와 kill). 구현 → `REF-node-ui-impl.md` "③ 트리 상태 스토어".

## 오버플로 — Grid 인스턴스 추가 (2026-08-19) + 칼럼 단위 스냅 (2026-09-29)
- 한 Grid는 최대 2×2=4타일. 넘치는 타일은 **별도 `<tile-layout>`(=Grid 인스턴스)를 옆에 추가**해 가로 스크롤로 이어붙인다(`pages/index.vue`의 `#Index` `overflow-x:auto`+`flex-shrink:0`이 하부 배선). 좁은 화면은 Grid 하나의 칸 수가 줄어 Grid가 더 많아질 뿐, 숨겨지는 타일은 없다.
- **Grid 간 스크롤 = 칼럼 단위 스냅**: 스냅 단위는 Grid 하나가 아니라 **칼럼 = Grid 가로 절반**. G1 오른쪽 칼럼 + G2 왼쪽 칼럼처럼 **Grid 경계에 걸친 위치(0.5, 1.5 …)에도 스냅**된다.
  - 칼럼은 **물리 가로 절반**이고 Band 경계와 무관(axis='row' Grid의 가로바 타일도 절반 지점에서 스냅).
  - 가로 용량이 1칸(Grid 영역 가로 < `W_TH`)이면 **Grid 단위 스냅으로 폴백**.
  - 구현: `#Index{scroll-snap-type:x mandatory}` + 각 Grid 안에 `columnStops()` 오프셋마다 스냅 앵커(`scroll-snap-align:start`인 절대배치 1px 요소). Grid 자체에는 snap-align을 안 준다.
  - 칼럼 이동 버튼(‹ ›)·Grid 탭(VPagination)·칼럼 위치 표시 → `REF-node-ui-overview.md` "헤더 내비게이션".
- **빈 오른쪽 칼럼 줄이기 (확정 2026-09-29)**: 오른쪽 칼럼(위·아래 두 칸)이 **통째로 빈 Grid는 위치와 상관없이**(마지막 Grid든 중간 Grid든) **1칼럼 폭**으로 표시한다. 가로는 스크롤 길이로 드러나므로 빈 공간이 쓸모없다는 판단. **세로 빈칸은 줄이지 않고 `빈 칸`으로 둔다.**
  - 판정: `pack`(시안 `toGrids`)이 Grid마다 `cols = (occ[1][0], occ[1][1] 둘 다 빔) ? 1 : 2`를 붙인다. 가로 1.0 타일이 있는 Grid(axis='row')는 오른쪽 칼럼이 항상 차 있으므로 해당 없음. 가로 용량 1칸인 화면(폰 세로)도 모든 타일이 가로 1.0이라 해당 없음.
  - 중간 Grid에서도 생기는 경우: 세로 1.0 타일(0.5×1.0) 다음에 가로 1.0 타일이 오면 들어갈 자리가 없어 다음 Grid로 넘어가고, 앞 Grid의 오른쪽 칼럼은 빈다.
  - 폭 = `(Grid 폭 - band gap) / 2`(칼럼 하나 폭과 같게). 이 Grid의 스냅 앵커는 하나(`columnStops`에 `cols` 인자 추가, `cols=1`이면 `[0]`).
  - Grid 폭이 제각각이 되므로 "Grid 몇 개째 보이나" 같은 계산은 Grid마다 자기 폭을 써야 한다(시안의 `grids[0]` 폭 가정 버그를 여기서 고침).
  - 비교 시안: "마지막만 줄임"(기각) / "전부 줄임"(채택) — 링크 `user/links.md`. 원본 시안(Tz9D…)에는 미반영, 구현 기준 시안(전체보기)에는 반영됨.
- **Grid 크기 = 헤더/푸터 제외 뷰포트 100% (2026-08-19 제안, 미확정)**: 앱 셸을 세로 flex column(`AppHead`/`main(flex:1;min-height:0)`/`AppFoot`)으로 짜면 `#Index{height:100%}`만으로 해결. 단 `AppHead`/`StickyBox`가 `position:fixed`면 flex 흐름에서 빠지므로, 그 경우 새 ResizeObserver 대신 `StickyBox`의 `rootClient`/`maxClient` 보고값을 CSS 변수(`--header-h`/`--footer-h`)로 노출해 `calc()`로 뺀다. **확인됨(2026-09-29)**: 헤더 = `VAppBar`(fixed), `VMain`이 padding으로 비킴 → `REF-node-ui-impl.md` "확인된 환경 사실".
